# Handoff: Панель «Тёплый пол» для Home Assistant

## Overview
Одна страница в боковом меню Home Assistant (custom panel), полностью заменяющая приложение Danfoss Ally для 6 термостатов тёплого пола Danfoss Icon2 RT (Гостиная, Спальня, Гостевая, Кабинет, Ванная, Душевая). Без вкладок: сводка по дому, подробная страница каждой комнаты (с недельным расписанием) и отпуск — на одной странице с боковым меню.

Серверная часть уже есть: интеграция `danfoss_local` (сущности и сервисы описаны в `reference/data-sample.json`, задание — в `reference/prompt.md`).

## About the Design Files
Файлы в этом пакете — **дизайн-референсы, сделанные в HTML** (`Панель отопления v2.dc.html` + `support.js`, открывается в браузере). Это прототип внешнего вида и поведения, а не продакшен-код. Задача — **воссоздать этот дизайн в среде Home Assistant** (custom panel на Lit/`LitElement` в стиле HA frontend, либо панель через `panel_custom` с `ha-card`-подобными карточками), используя существующие паттерны HA: `hass.states`, `hass.callService`, тему HA (`--primary-background-color`, `--card-background-color`, `--primary-text-color`, `--secondary-text-color`, `--divider-color`, `--ha-card-border-radius`, `--ha-card-box-shadow`). Всё, что в макете сделано своими токенами, следует привязать к переменным темы HA, чтобы светлая/тёмная тема работала автоматически.

## Fidelity
**High-fidelity.** Компоновка, размеры, шрифты, скругления и состояния — итоговые; воспроизводить максимально близко, но цвета брать из темы HA (макетные значения ниже — референс для светлой и тёмной темы).

## Общая структура страницы
- Контейнер: `max-width: 1280px; margin: 0 auto; padding: 16px 16px 32px; display:flex; flex-direction:column; gap:14px`.
- Шрифт: Roboto (в HA уже есть), базовый 15px / line-height 1.45.
- **Шапка**: заголовок «Тёплый пол» (22px/500), рядом серым 13.5px «Danfoss Icon2 · <день недели> <ЧЧ:ММ>», справа кнопка-пилюля переключения темы (в HA — не нужна, тема управляется HA).
- **Баннер активного отпуска** (только когда отпуск действует): фон `--acc-soft`, рамка 1px `--acc`, радиус 14px, padding 14px 18px; текст «Отпуск активен» (14.5px/700, `--acc-ink`) + сводка («„В отсутствии“ · 17.0° · до 24.12 18:00 · 6 помещ.»); справа кнопки «Исправить» (контурная) и «Выйти из режима» (заливка `--acc-ink`).
- **Двухколоночный блок** `display:flex; gap:14px; flex-wrap:wrap; align-items:flex-start`:
  - `aside` 232px (на ширине ≤760px — 100% ширины, список становится горизонтальной прокручиваемой полосой).
  - контент `flex:1; min-width:min(100%,340px)`.

## Interactions & Behavior
- **Цель ±0.5** (карточка сводки и страница комнаты): создаёт ручное состояние `{temp, by:'panel'}` — термостат держит эту температуру до следующей границы расписания; уставки режимов не меняются. Пределы 4.0–35.0 (реально — `lower/upper_temperature`). Недоступно у комнат в активном отпуске.
- **Дропдаун режима / быстрые кнопки**: ручное состояние `{mode, by:'panel'}` до границы расписания. Повторный тап на активную быструю кнопку снимает.
- **Вернуться к расписанию**: сбрасывает ручное состояние (в HA — вернуть `preset_mode` по расписанию / включить расписание).
- **Происхождение цели** определяется по `sensor.<id>_setpoint_change_source`: `Manual` → «изменено на термостате», `Externally` → «изменено извне», `schedule` → по расписанию. «До чего» — `next_change_at`/`next_mode` из `sensor.<id>_schedule`.
- **Расписание, перетаскивание**: `pointerdown` на ручке → `pointermove` по `window`; позиция = `round((x − barLeft)/barWidth · 1440 / 30) · 30`, зажата: начало ≥ конца предыдущего окна и ≤ конец−30; конец ≤ началу следующего и ≥ начало+30. `pointerup/pointercancel` — снять слушатели; клик по окну после перетаскивания не открывает редактор (флаг `dragged` ~50 мс). Сохранение — `set_schedule` с программой `{"days":[[{"start":"06:00","end":"08:00"},…],…7]}`.
- **Отпуск**: `set_holiday` (`kind: away|at_home`, `start/end`: datetime для away, date для at_home, `all` или список устройств), `clear_holiday`. При активном отпуске у входящих комнат: режим «Отпуск/Отпуск дома», бейдж «отпуск», быстрые режимы и степпер цели заблокированы; «Исправить» открывает форму с текущими значениями (переход на сводку).
- **Обновление данных** — раз в 30 с / по событиям `hass.states`.
- **Сенсорные экраны**: все цели касания ≥ 40–44px, ничего не завязано на hover.
- **Адаптив**: ≤760px — меню становится горизонтальной полосой над контентом; сетка карточек и ряды показателей переносятся (`flex-wrap`).

## State Management
- `view`: −1 | 0..5.
- `rooms[]`: `{id, name, air, floor, hum, bat, sp{home,away,pause,holiday}, lower, upper, enabled, program[7][][2] (минуты), heating, override: null | {mode?, temp?, by:'panel'|'device'}, preset, lock, preheat, fault}` — в HA всё это читается из сущностей (см. `reference/data-sample.json`).
- `edit`: `{d, i}` | null — редактируемое окно; `menu`: индекс комнаты с открытым дропдауном | null; `rare`: bool; `copied`: bool (таймер 2.5 с).
- `vac`: null | `{kind, temp, rooms[6], count, startLabel, endLabel}`; `vacOpen`: bool; `vf` (форма): `{kind:'away'|'at_home', when:'now'|'plan', start, end, rooms[6], temp}`.
